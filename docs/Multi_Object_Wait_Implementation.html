Document: Multi-Object Wait (waitobj) Implementation Summary
Project: mCertiKOS / OS teaching kernel
Date: April 2026

1. Objective

Implement a kernel-level multi-source wait so one thread can register timer, keyboard, and optional software sources on a wait object, block with thread_sleep, wake when any source becomes ready via thread_wakeup, and return which source fired. One waiter per wait object; static pools (no kmalloc).

2. Architecture (summary)

  • Wait object: source list, spinlock_t lk, owner_pid, used as the sleep channel (thread_sleep(wo, &wo->lk)).
  • Event source: id, type, ready, parent, next; timers add period_ms, next_fire_tick.
  • Global tick: waitobj_ticks in kern/sync/waitobj.c, advanced from the timer IRQ path.

4. System calls

NameRole
SYS_waitobj_createAllocate wait object; return wid.
SYS_waitobj_addAdd source (timer period in ms in arg).
SYS_waitobj_waitBlock until ready or timeout; return source id.
SYS_waitobj_signalSignal EVENT_SOFTWARE source.

5. Timer and keyboard integration

  • Timer: timer_intr_handler calls waitobj_on_timer_irq() (increment ticks, scan deadlines, event_notify). One unconditional KERN_INFO when a timer source fires.
  • Keyboard: IRQ dispatches to keyboard_intr(); after console buffering, waitobj_console_input_notify().

6. Boot note

kern/init/init.c creates idle then wait_demo and switches to wait_demo, so when wait_demo sleeps in waitobj_wait the scheduler can run idle (required because thread_sleep dequeues another thread).
